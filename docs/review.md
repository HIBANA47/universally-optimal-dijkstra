# Universal Optimality of Dijkstra via Beyond-Worst-Case Heaps 综述

> 论文：Haeupler, Iacono, Izumi, Rozhoň, Tarjan. FOCS 2024.

# 1 引言

在算法课上，我们学到 Dijkstra 算法配合 Fibonacci 堆可以在 $O(m + n \log n)$ 时间内解决单源最短路径问题。这个界被认为是最优的——但仔细想想，这个"最优"是对所有 $n$ 个节点 $m$ 条边的图取最坏情况。如果图是一条链，Dijkstra 其实只需要 $O(n)$ 时间；如果图是一棵树，也远不需要 $n \log n$。最坏情况分析把这些"简单"的图和"困难"的图混为一谈，给出的保证过于悲观。

这就引出了一个自然的问题：能不能有一个算法，它在每种具体的图结构上都自动达到最优？也就是说，如果图是链，它就跑 $O(n)$；如果图是星形，它就跑 $O(n \log n)$——不需要我们针对每种图单独设计算法。

这就是**普适最优性**（universal optimality）的核心思想。这个概念最早出现在分布式算法领域 [GKP98; HWZ21]，而本文（Haeupler et al., FOCS 2024）首次将它引入标准的顺序计算模型，并证明了一个漂亮的结果：

> Dijkstra 算法配合一种具有"工作集性质"的优先队列，是距离排序问题的普适最优算法。

论文还设计了满足这一性质的堆数据结构（对 Fibonacci 堆的严格改进），并进一步给出了在比较次数上也普适最优的算法变体。

## 2 背景

### 2.1 Dijkstra 算法与 Fibonacci 堆

Dijkstra 算法 [Dij59] 维护一个优先队列，反复执行以下操作：取出队列中距离最小的节点（DeleteMin），然后松弛它的邻居（DecreaseKey）。使用二叉堆时，每次操作 $O(\log n)$，总时间 $O((m+n) \log n)$。Fredman 和 Tarjan [FT87] 引入 Fibonacci 堆，将 Insert 和 DecreaseKey 降到摊销 $O(1)$，DeleteMin 为摊销 $O(\log n)$，总时间改进为 $O(m + n \log n)$。

如果问题要求按距离排序输出所有节点（而不仅仅是计算距离），那么 $O(n \log n)$ 项是不可改进的——因为在星图上，距离排序等价于对 $n-1$ 个数排序，比较模型下需要 $\Omega(n \log n)$ 次比较。

### 2.2 排序下界的信息论论证

在比较模型中，每次比较返回三种结果（$<$、$=$、$>$），$q$ 次比较最多区分 $3^q$ 种情况。如果问题有 $N$ 种可能的输出，则至少需要 $\log_3 N$ 次比较。对 $n$ 个元素排序，$N = n!$，所以排序需要 $\Omega(n \log n)$ 次比较。这个论证在本文的证明中会反复出现。

### 2.3 三种最优性

论文区分了三个层次的最优性概念：

**存在性最优**（existential optimality）：对所有 $n$ 节点 $m$ 边的图，算法的最坏情况运行时间是最优的。这就是我们课上说的"最优算法"，形式化为：

$$\sup_{G \in G_{n,m}} \sup_{w} A(G,w) \leq O(1) \cdot \inf_{A^*} \sup_{G \in G_{n,m}} \sup_{w} A^*(G,w)$$

**普适最优**（universal optimality）：固定图拓扑 $G$，算法在 $G$ 上对所有权重 $w$ 的最坏表现，不差于任何正确算法在 $G$ 上的最坏表现：

$$\forall G: \sup_{w} A(G,w) \leq O(1) \cdot \inf_{A^*} \sup_{w} A^*(G,w)$$

直觉上，普适最优算法能自动适应图的结构。如果某类图上存在快速算法，普适最优算法在这类图上也必须快。

**实例最优**（instance optimality）：对每一个具体输入 $(G,w)$ 都最优。这是最强的要求，但对距离排序问题不可能实现——因为可以构造一个"硬编码"算法：检查输入是否是某个特定 $(G_0, w_0)$，如果是就直接输出答案（$O(1)$ 时间），否则跑一个慢算法。任何实例最优算法都必须和这种"作弊"算法竞争，这是不可能的。

普适最优性恰好位于两者之间：比存在性最优强（逐图保证），比实例最优弱（不逐权重保证），是一个既有意义又可实现的甜蜜点。

### 2.4 距离排序问题与计算模型

本文始终考虑**距离排序问题**（Distance Ordering, DO）：给定有向图 $G$（$n$ 个节点、$m$ 条边）、边权重和源点 $s$，按到 $s$ 的距离递增顺序输出所有顶点。

计算模型是**比较-加法模型**：边权重是黑盒，算法只能对权重做加法（Add）和比较（Compare）。查询复杂度定义为 Compare 操作的次数。这个限制是必要的——如果允许任意操作权重，下界论证就不成立了。

## 3 相关工作

### 3.1 最短路径算法

Dijkstra 算法 [Dij59] 是单源最短路径问题的经典算法，配合二叉堆的最坏情况时间为 $O((m+n) \log n)$。Fredman 和 Tarjan [FT87] 引入 Fibonacci 堆后，将运行时间改进到 $O(m + n \log n)$——如果要求按距离排序输出所有节点，这个界在比较模型下是最优的。

如果只要求计算距离而不要求排序输出，Duan, Mao, Shu 和 Yin [Dua+23] 最近给出了一个突破：对无向图以期望时间 $O(m \sqrt{\log n \log \log n})$ 解决最短路径问题，打破了 $O(m + n \log n)$ 的屏障。不过他们的方法依赖于整数权重和随机化，与本文的比较-加法模型框架不同。

此外，如果假设权重是整数或最大最小权重比有界，还有一系列接近线性的最短路径算法 [FW93; Tho99; Tho04]，但这些结果同样在本文的模型之外。

### 3.2 普适最优性的起源

"普适最优性"这个概念最早由分布式算法领域的研究者提出 [GKP98; HRG22; GZ22]。在分布式计算中，图的拓扑（即通信网络的结构）是固定的，研究者关心的是：对于每种具体的网络拓扑，算法能否自动达到最优？这个框架下已经发展出了近似最短路径等问题的普适最优分布式算法 [HWZ21; Zuz+22; Roz+22]。

本文的新意在于：将普适最优性从分布式计算引入标准的顺序计算模型。据作者所知，这是该概念在分布式算法之外的首次使用。

### 3.3 实例最优性

实例最优性 [FLN01; ABC17] 是超越最坏情况分析中的"黄金标准"，在 Roughgarden 的教材 [Rou21] 中占据重要位置。但实例最优性是一个极强的要求，很少能被满足。

对距离排序问题，实例最优性不可实现：任何算法都可以"猜测"输出（即猜测线性排序和最短路径树），然后在线性时间内验证猜测是否正确。这意味着存在"作弊"算法在特定输入上只需 $O(n)$ 时间，任何实例最优算法都必须与之竞争，这是不可能的。

因此，实例最优性领域的结果通常需要同时限制计算模型（否则难以获得下界）并放宽实例最优性的定义。例如 Afshani, Barbay 和 Chan [ABC17] 对几何问题（如 2D 凸包）达到了"无序 oblivious 实例最优性"——一种放宽版本。有趣的是，凸包问题可以视为排序的扩展，类似于距离排序问题也是排序的扩展（通过星图）。

### 3.4 工作集性质与数据结构

工作集性质最早出现在二叉搜索树的文献中。Sleator 和 Tarjan [ST85] 提出伸展树（splay tree），证明了它满足工作集性质等一系列超越最坏情况的保证。伸展树的动态最优性猜想至今仍是数据结构领域最著名的开放问题之一。

对于堆和优先队列，Iacono [Iac00] 证明了配对堆（pairing heap）满足工作集性质，但他的分析不包括 DecreaseKey 操作。Elmasry [Elm06] 给出了一种满足更强版本工作集性质的堆，但同样没有 DecreaseKey。Elmasry, Farzan 和 Iacono [EFI12] 的实现支持 DecreaseKey，但不具有摊销常数时间。

本文的贡献在于：给出了一个同时满足工作集性质和 $O(1)$ 摊销 DecreaseKey 的类 Fibonacci 堆（定理 1.5），填补了上述工作的空白。

### 3.5 后续工作：拓扑堆排序

本文预印本公开后，Haeupler 等人 [Hae+24] 将相同的技术应用于"部分信息下的排序"问题（可追溯到 Fredman [Fre76]）：给定一个 DAG $G$ 表示已知的偏序关系，通过最少的比较找到与 $G$ 一致的未知全序。他们提出的"拓扑堆排序"算法执行 $O(\log T)$ 次比较（$T$ 为 $G$ 的拓扑序数），运行时间 $O(n + m + \log T)$，两个界都是最优的。该算法同样使用工作集堆，并且其普适最优性的证明直接复用了本文的框架。

## 4 核心技术

### 4.1 工作集与工作集性质

Fibonacci 堆的 DeleteMin 代价是 $O(\log n)$，其中 $n$ 是堆中元素总数。但仔细想想，这个代价其实过于悲观——如果堆里大部分元素是很早之前插入的"老住户"，而最近才插入的元素只有几个，那提取最小值时真正需要"竞争"的其实只有这几个新元素。

论文引入了**工作集**的概念来精确刻画这一点：

> 对于堆中的元素 $x$，其工作集 $W_x$ 定义为：在 $x$ 之后插入、且在 $x$ 被提取时仍然存在于堆中的元素集合（包含 $x$ 本身）。取所有时刻中 $|W_{x,t}|$ 最大的那个时刻。

直觉上，$|W_x|$ 衡量的是"在 $x$ 的'生命周期'内，有多少比它更新的元素和它同时存在于堆中"。如果 $x$ 是最近才插入的，$W_x$ 很小；如果 $x$ 很早就插入了，期间有大量新元素进出，$W_x$ 就大。

基于此，论文定义了**工作集性质**：一个优先队列如果满足 Insert、FindMin、DecreaseKey 为 $O(1)$，DeleteMin 为 $O(1 + \log |W_x|)$（$W_x$ 是被提取元素的工作集），则称其具有工作集性质。

对比 Fibonacci 堆：Fibonacci 堆的 DeleteMin 是 $O(\log n)$，而工作集堆是 $O(\log |W_x|)$。由于 $|W_x| \leq n$，工作集堆严格不差于 Fibonacci 堆；在很多情况下（比如链状图），$|W_x|$ 远小于 $n$，改进是实质性的。

### 4.2 工作集堆的构造

论文给出了一个黑盒构造：给定任意一个类 Fibonacci 堆（比如就是 Fibonacci 堆本身），可以在其上构建一个满足工作集性质的新堆。

构造的核心思想是**分层**：维护一列堆 $H_1, H_2, H_3, \ldots$，其中第 $i$ 个堆 $H_i$ 的大小最多为 $2^{2^i}$（双指数增长）。规则如下：

1. 新元素总是插入最小的堆 $H_1$。
2. 如果某个堆 $H_i$ 的大小超过上限，就把它和相邻的 $H_{i+1}$ 合并（类似二项堆的进位）。
3. 保持一个不变式：编号大的堆包含较旧的元素。

为什么这能保证工作集性质？关键观察是：当一个元素从 $H_i$ "升级"到 $H_{i+1}$ 时，说明在 $H_i$ 和触发合并的携带堆中至少有 $2^{2^i - 1}$ 个比它更新的元素。因此，处于 $H_i$ 中的任何元素，其工作集大小至少为 $\Omega(2^{2^i})$。另一方面，$H_i$ 最多有 $2^{2^i}$ 个元素，所以从 $H_i$ 中提取的代价为 $O(\log 2^{2^i}) = O(2^i)$，而 $\log |W_x| \geq \log(2^{2^i}) = 2^i$。两者匹配，得到 DeleteMin 代价 $= O(1 + \log |W_x|)$。

选择双指数（而非单指数 $2^i$）增长是为了让堆的层数只有 $O(\log \log n)$，从而在查找最小元素所在的堆时开销可忽略。

### 4.3 为什么工作集性质蕴含普适最优性

用一个例子来说明。考虑论文中的图 $G_1$：源点 $s$ 连接一条长链 $v_1, v_2, \ldots, v_r$（$r = n - t - 1$），同时 $s$ 还连接 $t$ 个叶节点 $u_1, \ldots, u_t$。

在这张图上运行 Dijkstra：
- 链上的节点 $v_1, \ldots, v_r$ 逐个被提取，每个被提取时工作集大小为 $O(1)$（因为链上后一个节点总是紧接着被插入）。
- 叶节点 $u_1, \ldots, u_t$ 的工作集大小为 $O(t)$（它们几乎同时被插入堆中）。

总代价：$O(n + t \log t)$。

这已经是最优的——因为对 $u_1, \ldots, u_t$ 按距离排序等价于对 $t$ 个数排序，需要 $\Omega(t \log t)$ 次比较。任何算法在这张图上都不可能做得更好。

如果用 Fibonacci 堆，DeleteMin 代价是 $O(\log n)$，总代价变成 $O(n \log n)$——对这张图来说是不必要的浪费。工作集堆通过"按实际竞争者数量收费"，自动适配了图的结构。

### 4.4 主要定理

**定理 1.2**（普适最优 Dijkstra）：对于任意图 $G$ 和权重 $w$，使用具有工作集性质的优先队列的 Dijkstra 算法，其运行时间为 $O(OPT_Q(G) + m + n)$，其中 $OPT_Q(G)$ 是距离排序问题在图 $G$ 上的最优查询复杂度。即，Dijkstra 在每张图上都自动达到最优。

**定理 1.5**（工作集堆的存在性）：存在一个具有工作集性质的类 Fibonacci 优先队列，即 Insert、FindMin、DecreaseKey 为 $O(1)$，DeleteMin 为 $O(1 + \log |W_x|)$。

## 5 证明思路

- 上界：算法代价由 DeleteMin 主导，总代价 $= \sum \log |W_x|$
- 下界框架：信息论 → 障碍序列 → 排序下界 $\Omega(\sum |B_i| \log |B_i|)$
- 区间形式化：每个节点对应 $[\text{插入时间}, \text{提取时间}]$
- 相交着色与能量：$E(C) = \sum c_i \log c_i$
- 贪婪分析（引理 3.14）：$E(C) \geq cost(I)$，上下界匹配
- 探索树 vs SSSP 树：为什么必须用探索树

## 6 总结

- 论文的核心贡献评价
- 工作集堆作为独立数据结构结果的意义
- 局限性：比较次数普适最优需要更复杂的算法（第 5 节）
- 对后续研究的启发：普适最优性框架可能适用于更多图算法问题
